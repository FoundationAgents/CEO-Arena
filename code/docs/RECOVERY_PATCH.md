# 0.15.2：故障恢复与断点升级

本补丁修复执行恢复，不更换模型、Key、推理档位、seed、经济方程、Rule 或 Score。
决策 v9／运行时 v4 的数据格式保持兼容；源码指纹真实变化，旧数据不得伪装为全程新版。

## 三条规则

1. `length` 截断且仅有 reasoning 的响应不原样回传。原始审计保留；旧会话只修复
   与既有截断提示精确匹配的坏消息。合法历史、草稿、私有文件、工具回执与用量保留。
2. 临时网络、流式与可恢复服务端错误在剩余额度内退避。自动退避计入 60 分钟，
   排队和人工暂停不计入；不重置已记录的时间、Token 和回复数，不追造旧版未记录的等待。
3. 额度耗尽不再无限等待：记录 `timeout` 和原始故障分类，保持当前持续政策后结算。
   不自动提交草稿，不重放旧研发／扩容／投标。连续三次 HTTP400 停止该 Run，交给下述
   巡检恢复规则；认证、权限、模型身份或必要持久化错误仍等待处理。其他 Run 继续。统计保留
   `recovery.infrastructure_timeout_count`，不得把接口异常当成成功 seal。

## 原实验续跑：先升级，再 resume

先安全停止目标 Runner，确认 Worker 与活跃租约均为零，保留看板和 SSH 隧道。
在已完成离线测试的新发布目录中运行（无需 API Key，不调用模型）：

```bash
python scripts/migrate_recovery_patch.py /absolute/campaign-output
python scripts/migrate_recovery_patch.py /absolute/campaign-output \
  --apply --expected-old-plan-hash <dry-run-reported-hash>
```

迁移只允许本补丁白名单内的源码变化；模型、参数、预算、Rule、经济规则不符会拒绝。
逐 Run 验证历史经济回放、状态哈希、已封存回执、用量和原始轨迹；保留原始计划、
manifest、SQLite 一致性备份和被修改的绑定文件。新计划使用真实的新源码指纹。
`recovery-patches/` 保存旧→新版本回执及每个 Run 的生效日／窗口。
半迁移标记存在时禁止启动，不可手工删除标记绕过检查。

通过迁移后，用原 TOML、原输出目录恢复。已结算天数不重算；当前周已提交的 CEO
不再调用；只有缺失决策的公司续写或按已耗尽额度收尾。实际 API 仍可能对中断中的
未完成请求收费，本补丁不保证零额外费用或 48 小时内完成。

此一次性工具拒绝覆盖已发布结果或已完成回放回执；如未来已有 completed Run，
必须保留其原始版本证据，不能机械套用这次升级。

## 报告和巡检

最终方法可以描述补丁后的系统；续跑轨迹必须附带各 Run 的升级位置与基础设施
超时次数，不能声称全部历史由同一版 Harness 生成。正常模型错误、接口故障和
人工介入分开记录，不能为改善分数选择性重跑。

每 30 分钟巡检读取真实天数、当前决策年龄、错误和进程，而非仅看 running 心跳。
健康运行不修改；发现可证实的恢复缺陷才测试、提交、部署并保留版本记录。
身份或凭证故障不能通过放宽白名单、改模型或更换 Key 自动解决。

### 单独批准的 Sol 回包别名

2026-09-13 用户另行批准仅将 `gpt-6-sol` 加入请求 `gpt-5.6-sol` 的回包白名单。
这不是自动放开其他身份，也不改变请求模型或其他运行参数。该配置变化需要独立的
`sol-return-alias-20260913` 升级记录；不能重跑上面的已应用 Harness 迁移。
它保留经济断点、原始身份日志、所有用量和已封存决策，只解除与该精确别名对应的
失败锁。其他身份、权限故障仍保持待处理。

### 自动恢复：接口重试与单窗口重做（当前规则）

同一逻辑请求连续 HTTP400 最多尝试三次，即首次请求加两次重试，第三次仍失败即停止该 Run。
有效模型回复后计数重置；不同公司独立计数。计数写入 allowance.failure，暂停恢复
不会清零；已累计三次或更多的旧失败不能通过普通 resume 重新获得尝试。默认等待
1、2 秒；上游 Retry-After 要求更久时予以尊重。等待仍计入原决策额度，已提交的其他 CEO 不重做。

用户已授权每 30 分钟巡检直接处理普通失败，不再逐次询问。范围不仅是 HTTP400，还包括
流式解析失败（如 `stream_decode/InvalidProviderOutput`）、普通接口或输出异常，以及能明确
定位到 CEO 窗口的 Worker 故障。只有 Run 确实进入 `failed` 才触发单窗口重做；HTTP400
仍先按上述规则尝试三次，其他普通故障无需凑满三次 HTTP400。仍在运行、退避、正常预算
收尾，或已提交／结算的决策不重做。进程中断优先保留全部历史并从断点续跑。

- 仅重做失败模型的当前窗口，世界状态、之前窗口、其他 CEO 的已提交决策和健康 Run 不变。
- 把当前会话、草稿、额度、原始轨迹与计时文件移入恢复归档，不永久删除。旧 Token、费用和
  故障次数仍计入实际总消耗；新尝试使用原配置的决策预算，并在审计中与旧尝试分开记录。
- 每次重做的私有文件都必须恢复到该窗口最初起点，不能携带此前失败尝试的新增记忆。
  所有尝试均没有成功写入时原样保留；有写入时只能按完整文件操作回执链中的
  previous/content 精确逆序还原，并保留原件。存在缺失回执、内容不匹配或不明确状态时停止，
  不猜测、不清空长期记忆。
- 每个 `(run_id, company_id, window)` 最多自动重做三次，不含原始尝试；此前已重做的次数
  一并累计，所有错误类型共享这三次，不因错误类型、重启、升级或中途有效回复清零。
  当前尝试再次因普通故障失败，才在剩余次数内重做；第三次重做仍失败则保留现场并通知。
  已封存或已结算窗口不重做。
- 每次重做使用独立编号和归档，保留所有旧成本；扫描回执计数后先独占预留新编号，避免重复
  巡检重复启动。存在 prepared/archived 等未完成恢复操作时先核实，不直接新增下一次尝试。
  认证、身份、权限、账户额度／明确配置错误，以及无法证明可安全恢复的持久化损坏，不通过
  清空历史碰运气；只做安全核查、保留断点并通知，不擅自改模型或 Key。普通恢复无需再次
  确认；无法安全执行时说明阻碍，不反复询问或无限重试。此次仅扩展巡检策略，无需迁移或重启 Runner。

当前三次上限的部署使用独立升级记录；保留历史十次计数和已应用的迁移回执，不能重新应用旧迁移。
停止 Runner 并确认租约释放后，运行 `scripts/migrate_http400_retry.py <output> --max-attempts 3`
预检，再带 `--apply --expected-old-plan-hash <预检值>` 升级。此补丁只允许 `retry.py`
指纹改变，保留历史结果、断点、当前对话和费用记录；完成后从原 Campaign 继续运行。
